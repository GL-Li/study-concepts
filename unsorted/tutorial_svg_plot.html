Building an SVG Plot by Hand

Write a complete line chart (axes, ticks, gridlines, a data line and hover dots) as one plain-text SVG/XML file. No code, no libraries.

How to Use

The only tools you need are a text editor and a browser. Nothing to install or run.

# 1. Save the example below as plot.svg (any folder)
# 2. Open it in a browser:
xdg-open plot.svg        # Linux
open plot.svg            # macOS
explorer.exe plot.svg    # WSL / Windows
# optional: confirm the file is well-formed XML (prints nothing if OK)
xmllint --noout plot.svg
# or, without xmllint:
python3 -c "import xml.etree.ElementTree as E; E.parse('plot.svg'); print('valid')"

What to look for: a blue zig-zag line with 11 dots, gridlines and labeled axes. Hover a dot to see it turn red and show a tooltip such as x=16, y=25.89. Then experiment: change a number in the file, save, and refresh the browser to see what it affects.

What You'll Learn

  • SVG is XML: the prolog, comments, elements, attributes, nesting, self-closing tags and xmlns.
  • Coordinates & viewBox: the origin is top-left and y grows downward.
  • Styling with CSS: fill/stroke instead of color/background, plus :hover.
  • Paint order: later elements are drawn on top, because SVG has no z-index.
  • Margins with <g transform="translate()">: draw in plot-area coordinates.
  • Scales by hand: turning data values into pixel coordinates, including the y-flip.
  • Gridlines & attribute inheritance: set a class or attribute once on a <g> instead of on every child.
  • Tick labels: <text>, text-anchor and dominant-baseline.
  • Axes & transforms: how translate() rotate() places the vertical axis title.
  • The <path> mini-language: M and L draw the data line.
  • Dots & tooltips: <circle> plus a <title> child for hover text.
  • Embedding in HTML: <img>, inline <svg>, <object>, <iframe> and CSS backgrounds, and which ones keep hover working.

The Example

Copy everything below into a file named plot.svg and open it in a browser (commands in How to Use).

plot.svg (74 lines, plain XML):

<?xml version="1.0" encoding="UTF-8"?>
<!-- Hand-written SVG line plot of y = sin(x/2)*10 + x, for x = 0, 2, ..., 20 -->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 600 400" width="600" height="400">

  <!-- 1. Styles: SVG shapes use fill/stroke instead of color/background -->
  <style>
    text  { font: 12px sans-serif; fill: #586e75; }
    .grid { stroke: #eee8d5; }
    .axis { stroke: #586e75; }
    .line { fill: none; stroke: #268bd2; stroke-width: 2; }
    .dots circle { fill: #fdf6e3; stroke: #268bd2; }
    .dots circle:hover { fill: #dc322f; }
  </style>

  <!-- 2. Background: drawn first, so it is the bottom layer -->
  <rect width="600" height="400" fill="#fdf6e3"/>

  <!-- 3. Plot area: move the origin past the left (60) and top (20) margins.
       Plot area is 520 x 330. Scales (data -> pixels):
         px = x * 26             x:   0..20  ->   0..520
         py = (30 - y) * 8.25    y: -10..30  -> 330..0   (flipped) -->
  <g transform="translate(60,20)">

      <line x1="0" x2="520" y1="330" y2="330"/>

      <text x="-8" y="247.5">0</text>

    <text transform="translate(-40,165) rotate(-90)" text-anchor="middle">sin(x/2)*10 + x</text>

    <!-- 8. One dot per point; the <title> child becomes a hover tooltip -->

      <circle cx="260" cy="244.1" r="3"><title>x=10, y=0.41</title></circle>

1. SVG is XML

Why it matters: an SVG file is structured text. Learn the handful of XML rules and you can read or write any SVG.

<!-- plot.svg:1-3 -->
<?xml version="1.0" encoding="UTF-8"?>
<!-- Hand-written SVG line plot of y = sin(x/2)*10 + x, for x = 0, 2, ..., 20 -->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 600 400" width="600" height="400">
<!-- plot.svg:74 -->
</svg>
  • Line 1, the XML prolog <?xml version="1.0" encoding="UTF-8"?>, says "this is XML, in UTF-8". It's optional for SVG but conventional, and if present it must be the very first thing in the file.
  • Comments <!-- … --> are notes for humans and can span several lines. They can't contain --.
  • Elements look like <name attr="value">children</name>, or self-close as <name …/> when empty. Attribute values are always quoted, even numbers.
  • Nesting forms a tree with exactly one root (<svg>). Tags close in reverse order of opening, which is why the file ends with </g> then </svg>.
  • xmlns="http://www.w3.org/2000/svg" declares the SVG namespace. Without it a browser treats the file as generic XML and shows a text tree instead of a picture.
  • XML is strict, unlike HTML: an unclosed tag, an unquoted attribute or a bare & or < in text makes the whole file fail to render. Write them as &amp; and &lt;.

2. Coordinates & viewBox

Why it matters: every number in the file is a position in this coordinate system, and its y-axis points the opposite way from a math graph.

<!-- plot.svg:3 -->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 600 400" width="600" height="400">
  • viewBox="min-x min-y width height" defines the user coordinate system: 0–600 across and 0–400 down. Every coordinate in the file uses these units.
  • width/height set the size on screen. Change them to 1200/800 and the whole drawing scales up, still perfectly sharp. That's the "Scalable" in SVG.
  • The y-axis is flipped compared with the coordinate geometry you know. Section 6 handles that when converting data to pixels.

3. Styling with CSS

Why it matters: you already know CSS, but SVG shapes use a few different property names.

<!-- plot.svg:5-13 -->
  <!-- 1. Styles: SVG shapes use fill/stroke instead of color/background -->
  <style>
    text  { font: 12px sans-serif; fill: #586e75; }
    .grid { stroke: #eee8d5; }
    .axis { stroke: #586e75; }
    .line { fill: none; stroke: #268bd2; stroke-width: 2; }
    .dots circle { fill: #fdf6e3; stroke: #268bd2; }
    .dots circle:hover { fill: #dc322f; }
  </style>
SVG propertyHTML-CSS equivalentNotes
fillbackground / colorPaints the inside of a shape and the color of text.
strokeborder-colorPaints the outline. A <line> is only stroke, so without one it's invisible.
stroke-widthborder-widthIn user units, centered on the geometry.
fill: none(transparent)Needed on the line path, or the default black fill closes it into a blob.
  • A <style> element inside the SVG works just like in HTML: element selectors (text), classes (.grid), descendants (.dots circle) and pseudo-classes (:hover).
  • Elements opt in with class="…", exactly like HTML.
  • Styles can also be written as attributes, such as fill="#fdf6e3" on the background <rect>. These are "presentation attributes", and any CSS rule overrides them.

4. Paint order

Why it matters: SVG has no z-index. The order of elements in the file is the stacking order.

<!-- plot.svg:15-16 -->
  <!-- 2. Background: drawn first, so it is the bottom layer -->
  <rect width="600" height="400" fill="#fdf6e3"/>
  • <rect> without x/y starts at (0,0). With width="600" height="400" it covers the whole canvas, so it serves as the background.
  • The rest of the file follows the same rule: gridlines go before the line, and the dots come last so they sit on top of the line.

5. Margins & the <g> group

Why it matters: tick labels and axis titles need room outside the plot area, and you don't want to add an offset to every single coordinate.

<!-- plot.svg:22 -->
  <g transform="translate(60,20)">
<!-- plot.svg:73 -->
  </g>
  • <g> ("group") draws nothing itself. It is a container whose transform applies to all of its children.
  • Inside the group, a child at (0,0) appears at canvas (60,20). Every chart coordinate in the file is therefore relative to the plot area's top-left corner.
  • The plot area is 600 − 60 − 20 = 520 wide and 400 − 20 − 50 = 330 tall.
  • Negative coordinates such as x="-8" land in the left margin, which is exactly where the y tick labels go.

6. Scales by hand: data → pixels

Why it matters: SVG only understands pixels, so every data value has to be converted before you can write it into the file.

<!-- plot.svg:18-22 -->
  <!-- 3. Plot area: move the origin past the left (60) and top (20) margins.
       Plot area is 520 x 330. Scales (data -> pixels):
         px = x * 26             x:   0..20  ->   0..520
         py = (30 - y) * 8.25    y: -10..30  -> 330..0   (flipped) -->
  <g transform="translate(60,20)">
  • x: 20 data units fill 520 px, so px = x × 520/20 = x × 26.
  • y: 40 data units (−10 to 30) fill 330 px, which is 8.25 px per unit. Measuring down from the top value, (30 − y), produces SVG's downward direction.
  • The axis ranges are rounded outward to nice numbers so the ticks fall on tidy values.
  • Every coordinate in the file was computed with these two formulas, as the table shows:

7. Gridlines & inheritance through <g>

Why it matters: groups let you style many elements at once, which keeps hand-written SVG short and consistent.

<!-- plot.svg:24-31 -->
    <!-- 4. Gridlines at y = -10, 0, 10, 20, 30: the class on <g> styles every child -->
    <g class="grid">
      <line x1="0" x2="520" y1="330" y2="330"/>
      <line x1="0" x2="520" y1="247.5" y2="247.5"/>
      <line x1="0" x2="520" y1="165" y2="165"/>
      <line x1="0" x2="520" y1="82.5" y2="82.5"/>
      <line x1="0" x2="520" y1="0" y2="0"/>
    </g>
  • <line x1 y1 x2 y2/> draws a segment between two points. Each gridline runs across the plot (x1=0 to x2=520) at the pixel y of a tick, so data 0 sits at 247.5.
  • class="grid" sits on the group. CSS stroke is an inherited property, so all five lines get stroke: #eee8d5 without repeating the class.
  • The same trick works with presentation attributes, as the next section shows with text-anchor.

8. Tick labels

Why it matters: ticks are what let a reader turn a position on screen back into a number.

<!-- plot.svg:33-47 -->
    <!-- 5. Tick labels: y labels right-aligned left of the axis, x labels centered below -->
    <g text-anchor="end" dominant-baseline="middle">
      <text x="-8" y="330">-10</text>
      <text x="-8" y="247.5">0</text>
      <text x="-8" y="165">10</text>
      <text x="-8" y="82.5">20</text>
      <text x="-8" y="0">30</text>
    </g>
    <g text-anchor="middle">
      <text x="0" y="350">0</text>
      <text x="130" y="350">5</text>
      <text x="260" y="350">10</text>
      <text x="390" y="350">15</text>
      <text x="520" y="350">20</text>
    </g>
MarkupEffect
<text x y>label</text>Draws text. Unlike shapes, the content goes between the tags.
text-anchor="end"Right-aligns the y labels against x=-8, so -10 and 0 line up on their right edges.
dominant-baseline="middle"Centers the text vertically on y. By default y is the text baseline, so labels would sit above their gridline.
text-anchor="middle"Centers each x label under its tick: x = 5 × 26 = 130.
  • Both alignment attributes are set once on the parent <g> and inherited by every <text> inside it.
  • The x labels sit at y="350", 20 px below the bottom of the plot (330), inside the bottom margin.

9. Axes & transforms

Why it matters: an axis is just two lines, but placing rotated text takes knowing how transforms combine.

<!-- plot.svg:49-53 -->
    <!-- 6. Axes + titles (the y title is rotated, then moved into the left margin) -->
    <line class="axis" x1="0" y1="330" x2="520" y2="330"/>
    <line class="axis" x1="0" y1="0" x2="0" y2="330"/>
    <text x="260" y="372" text-anchor="middle">x</text>
    <text transform="translate(-40,165) rotate(-90)" text-anchor="middle">sin(x/2)*10 + x</text>
  • The x-axis runs along the bottom of the plot (y=330) and the y-axis runs down the left edge (x=0).
  • rotate(-90) turns counter-clockwise around the current origin. Text placed with x="-40" y="165" and then rotated would swing far away. So the text stays at (0,0), gets rotated in place, and is then moved.
  • Read transform lists right to left. They also stack with the parent group's translate(60,20).

10. The <path> line

Why it matters: <path> is SVG's universal shape. One element with a compact command string draws the whole data line.

<!-- plot.svg:55-57 -->
    <!-- 7. The data line: M = move to the first point, L = line to each next point -->
    <path class="line" d="M0,247.5 L52,161.6 L104,139.5 L156,186.4 L208,243.9 L260,244.1
                          L312,171.6 L364,77.8 L416,33.9 L468,65 L520,127.4"/>
CommandMeaningUseful for
M x,yMove the pen (no drawing)Start of every line
L x,yStraight line to (x,y)Line charts (used here)
H x / V yHorizontal / vertical lineStep charts, bars
C …Cubic Bézier curveSmoothed lines
ZClose back to the startFilled area charts
  • The coordinate pairs are exactly the (px, py) columns of the scale table.
  • Whitespace and newlines inside d don't matter, so long paths can wrap across lines (line 57).
  • Uppercase commands use absolute coordinates. Lowercase ones (m, l) are relative to the previous point.
  • fill: none from the .line CSS rule keeps it a line and not a filled shape.

11. Dots & tooltips

Why it matters: markers show where the real data points are, and <title> gives hover tooltips with zero JavaScript.

<!-- plot.svg:59-62 -->
    <!-- 8. One dot per point; the <title> child becomes a hover tooltip -->
    <g class="dots">
      <circle cx="0" cy="247.5" r="3"><title>x=0, y=0.00</title></circle>
      <circle cx="52" cy="161.6" r="3"><title>x=2, y=10.41</title></circle>
  • <circle cx cy r>: the center uses the same pixel pair as the matching path point, so each dot lands on a corner of the line.
  • A <title> child becomes the browser's native tooltip and is read by screen readers. The circle can't self-close here because it has a child.
  • The .dots circle:hover rule from the style block turns the hovered dot red. Hover state comes from CSS alone, no script needed.

Embedding the SVG in HTML

Why it matters: a .svg file is only one place SVG can live. How you put it into a web page decides whether hover, tooltips and CSS still work.

1. <img>: simplest, treated as a picture

<img src="plot.svg" alt="Line plot of sin(x/2)*10 + x" width="600">
  • Works like a PNG: easy to size and cache, and reusable across pages.
  • Static: :hover, <title> tooltips and scripts inside the SVG don't work, and page CSS can't reach in.

2. Inline <svg>: paste the markup into the page

<body>
  <h1>My chart</h1>
  <svg viewBox="0 0 600 400" width="600" height="400">
    <style> … </style>
    <rect width="600" height="400" fill="#fdf6e3"/>
    …
  </svg>
</body>
  • Copy everything from <svg …> to </svg>. Leave out the <?xml …?> line; xmlns is optional inside HTML.
  • Fully interactive: hover, tooltips, page CSS and JavaScript all work. Libraries such as D3 build plots this way.
  • No extra HTTP request, but the markup is copied into every page that uses it.
Styles leak out. A <style> inside an inline SVG applies to the whole page. The example's text { … } rule would restyle every SVG <text> on the page. Use specific class names, such as .plot1 text.

3. <object>: a separate file that stays interactive

<object data="plot.svg" type="image/svg+xml" width="600" height="400">
  <img src="plot.png" alt="Line plot">  <!-- fallback if the SVG fails -->
</object>
  • Hover, tooltips and the SVG's own CSS work, and the file stays reusable.
  • The SVG is its own isolated document: page CSS doesn't affect it and its styles don't leak out.
  • Content between the tags is shown only if the SVG can't load.

4. <iframe>: similar to <object>

<iframe src="plot.svg" width="600" height="400" style="border:0" title="Line plot"></iframe>
  • Interactive and isolated, like <object>, but with iframe quirks: a default border, and its size doesn't adapt to the content.

5. CSS background: decoration only

.hero { background: url("plot.svg") no-repeat center / contain; }
  • Static, like <img>, and invisible to screen readers. Use it for decorative graphics, never for data.

Which to choose

MethodHover / tooltipsPage CSS can style itSeparate reusable fileAccessible

Rule of thumb: use <img> for a static picture, inline <svg> for interactivity or JavaScript control, and <object> for a separate file that stays interactive.

Try it: compare static and interactive

Save this as embed.html in the same folder as plot.svg, open it in a browser, and hover the dots in each chart. Only the second one turns red and shows tooltips.

<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>Plot demo</title></head>
<body>
  <h1>Static (no tooltips)</h1>
  <img src="plot.svg" alt="Line plot" width="600">

  <h1>Interactive (hover the dots)</h1>
  <object data="plot.svg" type="image/svg+xml" width="600" height="400"></object>
</body>
</html>

open embed.html            # macOS
explorer.exe embed.html    # WSL / Windows

Key Takeaways

An SVG plot is a strict XML tree of shapes in a top-left, y-down coordinate system. A margin <g transform="translate()"> plus two linear formulas (with the y-axis flipped) turn data values into the pixel coordinates the shapes need. The chart itself is a few primitives (<line>, <text>, <path d="M…L…">, <circle>) written back to front and styled with fill/stroke CSS. Once you can write this by hand, the output of D3 or matplotlib is just markup you can read.
